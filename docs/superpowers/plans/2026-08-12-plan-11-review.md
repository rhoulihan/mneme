# Mneme Plan 11 — /mneme:review: Open-PR Triage and Ingestion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal (user directive):** "/mneme:review should ingest open PRs, identify any duplicate or already processed and/or classified facts, and ingest any potentially new facts into the knowledge-index skill.md and its subdirectories." Released as 0.6.0. Review runs on the CURRENT DIRECTORY (same cwd resolution and failure behavior as classify), requires the `gh` CLI, and is prompt-driven over deterministic rails: machine annotation labels every fact addition in every open PR as duplicate / declined / possibly-integrated / new, the agent proposes per-PR verdicts, and the USER approves each action.

**Architecture:** Three lanes of action, all human-gated. (1) **Merge** a clean PR: `gh pr merge` executed only on explicit per-PR user approval — that is the human merge the doctrine requires, exercised through the agent. (2) **Close** a fully-duplicate PR: `gh pr close --comment`, also per-PR approval, with a comment naming the existing unit ids that cover it. (3) **Extract** from mixed PRs: genuinely new facts are written into the knowledge-index facts directory on a `mneme/review-*` branch (reusing the classify rails generalized to a branch prefix) and finalized into mneme's own PR — main is never written. Deterministic annotation reuses the machinery that already exists: `units.semantic_hash` for exact duplicate detection against the repo, the declined ledger, and cross-PR collisions; the index (`mneme_index.search`) for possibly-integrated hints. The bundle labels are evidence, not verdicts — the agent and user decide.

**Tech Stack:** No new dependencies. `gh` required at runtime for review (clear MnemeError otherwise); tests shim `gh` on PATH exactly like Plan 05's PR tests.

**Depends on Plan 10:** `units.facts_dir`, the classify rails, `CLASSIFY_INSTRUCTIONS` conventions, and the canonical facts location. READ those files as they landed, not as their plans wrote them.

**Spec impact:** new §7.8 (review), §7.7 gains the fact-preservation gate; Task 8 updates the spec.

## Global Constraints

- All prior Global Constraints hold, including PR-only (mneme never writes a registered repo's `main`) and the Plan 09 path-containment discipline for every write derived from untrusted content (PR diffs are UNTRUSTED input: bullet text, file paths, and PR titles/authors all flow from contributors).
- PR-diff parsing is read-only and tolerant: malformed hunks, non-fact files, binary noise, and CRLF must never crash triage — unparseable additions are reported in a `skipped` list per PR.
- No `gh` action that mutates the remote (`pr merge`, `pr close`, comments) is ever run by the rails; those are agent actions the skill permits only after explicit per-PR user approval, and the skill must say so.
- Sanctioned test updates: none — this plan only adds files except `core/mneme_core/cli.py`, `core/mneme_core/classify.py` (rails generalization), `core/mneme_core/gitops.py`, `core/mneme_core/templates.py`, `skills/` (new skill), and the Task 8 docs/release set.
- READ every file before modifying. Run tests with `python3 -m pytest` from the repo root.

**Shared test shim** (repeated verbatim where needed) — a fake `gh` that serves canned PR data from files:

```python
import os
import stat


def shim_gh(tmp_path, monkeypatch, pr_list_json, diffs):
    """diffs: dict number->unified diff text, written to files the shim cats."""
    bindir = tmp_path / "fakebin"
    bindir.mkdir(exist_ok=True)
    (bindir / "prlist.json").write_text(pr_list_json, encoding="utf-8")
    for n, diff in diffs.items():
        (bindir / f"diff{n}.txt").write_text(diff, encoding="utf-8")
    gh = bindir / "gh"
    gh.write_text(
        "#!/bin/sh\n"
        'case "$*" in\n'
        f'  *"pr list"*) cat "{bindir}/prlist.json" ;;\n'
        f'  *"pr diff"*) n=$(echo "$@" | grep -o "[0-9]*" | head -1); cat "{bindir}/diff$n.txt" ;;\n'
        "  *) exit 1 ;;\n"
        "esac\n",
        encoding="utf-8",
    )
    gh.chmod(gh.stat().st_mode | stat.S_IXUSR)
    monkeypatch.setenv("PATH", f"{bindir}{os.pathsep}{os.environ['PATH']}")
```

### Task 2: PR-diff fact parsing (`review.py`, part 1)

**Files:**
- Create: `core/mneme_core/review.py`, `tests/core/test_review_parse.py`

**Interfaces:**
- Produces: `@dataclass PrFact(pr: int, file: str, stem: str, line: str, category: str, text: str, tags: list[str], verified: str | None, unit_id: str)`; `parse_added_facts(pr_number: int, diff: str) -> tuple[list[PrFact], list[str]]` — walks unified-diff hunks; an added fact line is a diff line starting `+- [` inside a file whose path (from the `+++ b/…` header) ends with `.md` and contains a facts directory segment (`facts/` at top level or under `skills/knowledge-index/`); parses the bullet with `units.parse_bullet_line` (strip the leading `+`; tolerate CRLF); malformed candidates go to the `skipped` list as `"PR <n> <file>:<reason>"`. `unit_id` = `units.fact_unit_id(stem, text)`. Added SKILL.md files are surfaced too: `parse_added_skills(pr_number, diff) -> list[dict]` with `{"pr", "file", "name"}` for any added `skills/<name>/SKILL.md` path (name from the path segment — content parsing not required; the agent reads the PR itself for judgment).

DIFF = """diff --git a/skills/knowledge-index/facts/deploys.md b/skills/knowledge-index/facts/deploys.md
--- a/skills/knowledge-index/facts/deploys.md
+++ b/skills/knowledge-index/facts/deploys.md

diff --git a/facts/legacy.md b/facts/legacy.md

+++ b/facts/legacy.md

+---

+++ b/README.md
@@ -1 +1,2 @@

    assert "Legacy-location addition" in texts

    assert not any("not a fact file" in t for t in texts)

**Interfaces:**
